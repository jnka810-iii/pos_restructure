# โหมดเซิร์ฟเวอร์บังคับเข้าสู่ระบบกับทุกคน รวมถึงเครื่องแม่ข่ายเอง

แทนที่ข้อยกเว้นของ [ADR 0001](0001-login-only-for-other-machines.md) เฉพาะตอนที่แอปเปิดรับจากภายนอก ส่วนโหมดเดสก์ท็อปกับไฟล์ `.exe` ยังเป็นไปตาม 0001 ทุกอย่าง

## ปัญหา

ADR 0001 ให้คำขอจาก `127.0.0.1` ผ่านด่านไปเลย โดยให้เหตุผลว่าคนที่นั่งอยู่หน้าเครื่องแม่ข่ายเปิดไฟล์ฐานข้อมูลด้วยโปรแกรมอะไรก็ได้อยู่แล้ว เหตุผลนั้นยังจริงอยู่สำหรับโหมดเดสก์ท็อป แต่พอ `run_server.bat` ผูกทุกอินเทอร์เฟซ ข้อยกเว้นนี้สร้างผลสองอย่างที่ไม่ได้ตั้งใจ

คนที่นั่งอยู่หน้าเครื่องแม่ข่ายเปิด `http://127.0.0.1:5020` แล้วเข้าใช้งานได้โดยไม่ผ่านหน้าเข้าสู่ระบบ ผู้ดูแลที่คาดว่าจะเห็นหน้าเข้าสู่ระบบจึงเข้าใจว่าระบบยังไม่ทำงาน

คำขอที่บันทึกจากเครื่องนั้นเก็บชื่อผู้บันทึกเป็น `เครื่องแม่ข่าย` ทั้งที่อาจมีหลายคนผลัดกันใช้เครื่องตัวเดียว ชื่อผู้บันทึกจึงบอกไม่ได้ว่าใครเป็นคนทำ

ที่สำคัญกว่าสองข้อนั้นคือ ADR 0001 เขียนไว้เองว่าข้อยกเว้นจะกลายเป็นช่องโหว่ทันทีที่มีอะไรส่งต่อคำขอจากเครื่องอื่นมาเป็น loopback เมื่อแอปเปิดรับจากภายนอกแล้ว เซิร์ฟเวอร์แยกคำขอของคนที่นั่งอยู่หน้าเครื่องออกจากคำขอที่ถูกส่งต่อมาไม่ได้

## สิ่งที่ตัดสินใจ

นโยบายเข้าสู่ระบบมาจาก host ที่แอปผูกจริง ไม่ได้มาจากที่อยู่ของผู้เรียกเพียงอย่างเดียว `serve()` ตั้ง `TRUST_LOCAL` เป็นจริงเมื่อ host ที่ผูกอยู่ใน `LOOPBACK` เท่านั้น และด่าน `require_login` ยกเว้นให้คำขอจากเครื่องนี้ก็ต่อเมื่อ `TRUST_LOCAL` เป็นจริง

`run_server.bat` และ `run_browser.bat` เรียก `serve()` ทั้งคู่ การเปิดให้ทั้งวงโดยไม่บังคับเข้าสู่ระบบจึงเขียนไม่ได้ เทส `the_lan_launcher_goes_through_the_one_entry_point_that_sets_the_policy` กันไม่ให้ตัวเปิดย้อนกลับไปเรียก `app.run` เอง

`serve()` ปฏิเสธที่จะเปิดเซิร์ฟเวอร์เมื่อยังไม่มีบัญชีสักคน เพราะด่านที่ใช้กับทุกคนบวกกับฐานข้อมูลที่ไม่มีบัญชี แปลว่าไม่มีใครเข้าได้เลย รวมถึงผู้ดูแลที่เพิ่งกดเปิด เดิม `run_server.bat` แค่เตือน

## ผลที่ตามมา

ผู้ดูแลต้องสร้างบัญชีด้วย `manage_users.py add` ก่อนเปิดเซิร์ฟเวอร์ครั้งแรก และต้องเข้าสู่ระบบทุกครั้งที่ใช้งานจากเครื่องแม่ข่าย นี่คือขั้นตอนที่เพิ่มขึ้นจริง และเป็นราคาของการรู้ว่าใครเป็นคนบันทึกคำขอแต่ละใบ

คำขอที่บันทึกในโหมดนี้เก็บชื่อคนที่เข้าสู่ระบบเสมอ ค่า `เครื่องแม่ข่าย` ยังใช้กับโหมดเดสก์ท็อปและ `.exe` ซึ่งไม่มีระบบบัญชี

`DELETE /api/positions` ยังผูกกับที่อยู่ของเครื่องตามเดิม คนที่นั่งอยู่หน้าเครื่องแม่ข่ายและเข้าสู่ระบบแล้วลบคำขอทั้งหมดได้ เครื่องในวงที่เข้าสู่ระบบแล้วยังทำไม่ได้

ไฟล์ `.exe` ไม่ได้รับผลกระทบ มันเสิร์ฟ `127.0.0.1` อย่างเดียวและไม่มี `manage_users.py` ติดไปด้วย การบังคับเข้าสู่ระบบกับมันจะทำให้ไม่มีใครสร้างบัญชีแรกได้ `TRUST_LOCAL` จึงตั้งต้นเป็นจริง และมีแต่ `serve()` ที่เปลี่ยนค่านี้

host ที่ไม่ใช่ `127.0.0.1` หรือ `::1` ทุกค่าบังคับเข้าสู่ระบบ รวมถึง `localhost` ซึ่งเป็น loopback จริงแต่สะกดต่างออกไป การเดาผิดทางนี้คือการขอรหัสผ่านเกินจำเป็น ไม่ใช่การเปิดช่องให้คนนอก
