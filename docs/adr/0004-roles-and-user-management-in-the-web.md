# บัญชีมีบทบาท และผู้ดูแลระบบจัดการบัญชีจากหน้าเว็บได้

ต่อจาก [ADR 0003](0003-server-mode-requires-a-login-from-everyone.md) ซึ่งทำให้ทุกคนในโหมดเซิร์ฟเวอร์ต้องเข้าสู่ระบบ ADR นี้ตอบว่าเมื่อเข้ามาแล้วใครทำอะไรได้บ้าง

## ปัญหา

หลัง ADR 0003 ทุกคนที่เข้าสู่ระบบได้มีสิทธิ์เท่ากันหมด เจ้าหน้าที่ที่กรอกคำขอกดลบคำขอของคนอื่นได้ และกดลบคำขอทั้งหมดได้ถ้านั่งอยู่หน้าเครื่องแม่ข่าย งานที่ย้อนกลับไม่ได้จึงอยู่ในมือของทุกคนที่มีบัญชี ทั้งที่หน่วยงานมอบหมายให้คนไม่กี่คนเท่านั้น

`manage_users.py` เขียนไว้แต่แรกว่าตั้งใจให้ไม่มีหน้าจัดการบัญชีในเว็บ เพราะเครื่องแม่ข่ายคือเครื่องของผู้ดูแลอยู่แล้ว เหตุผลนั้นใช้ไม่ได้อีกเมื่อระบบเปิดให้ทั้งวง LAN ใช้ การเพิ่มบัญชีให้เพื่อนร่วมงานกลายเป็นการเดินไปที่เครื่องแม่ข่าย เปิด Command Prompt และพิมพ์คำสั่งที่มีเครื่องหมายคำพูดภาษาไทย ผู้ดูแลที่ไม่ได้ใช้บรรทัดคำสั่งเป็นประจำทำพลาดได้ง่าย และทุกครั้งที่มีคนเข้าใหม่ก็ต้องทำซ้ำ

## สิ่งที่ตัดสินใจ

บัญชีมีคอลัมน์ `role` ที่เป็น `admin` หรือ `staff` และสิทธิ์ของแต่ละบทบาทอยู่ในตาราง `PERMISSIONS` ตารางเดียวใน `app.py`

ผู้ดูแลระบบลบคำขอ ลบคำขอทั้งหมด และจัดการบัญชีได้ เจ้าหน้าที่บันทึกและแก้ไขคำขอได้ แต่ทำสามอย่างนั้นไม่ได้ ความสามารถที่เจ้าหน้าที่ขาดไปคือความสามารถที่ย้อนกลับไม่ได้ทั้งหมด การแยกเส้นไว้ตรงนี้ทำให้กฎอธิบายได้ด้วยประโยคเดียวว่าใครลบอะไรได้

ทุกจุดที่ตรวจสิทธิ์อ่านจากตารางเดียวกันผ่าน `can()` และ route ที่ต้องคุมสิทธิ์ติด `@requires(<สิทธิ์>)` ไว้ หน้าเว็บได้ตาราง `PERMISSIONS` ทั้งตารางไปกับ `index()` แล้วซ่อนปุ่มที่ติด `data-perm` ไว้ตามบทบาทปัจจุบัน หน้าเว็บจึงไม่ได้เขียนกฎซ้ำ มันอ่านกฎชุดเดียวกับที่เซิร์ฟเวอร์บังคับใช้ การซ่อนปุ่มเป็นเรื่องของหน้าตาเท่านั้น คำขอทุกใบยังผ่าน `@requires` อยู่ดี

แท็บ "จัดการผู้ใช้งาน" เปิดได้เฉพาะบทบาทที่มีสิทธิ์ `manage_users` ใช้เพิ่มบัญชี แก้ชื่อและบทบาท ตั้งรหัสผ่านใหม่ และลบบัญชีได้ครบ ชื่อผู้ใช้เปลี่ยนไม่ได้หลังสร้างแล้ว เพราะเป็นสิ่งที่เจ้าของบัญชีพิมพ์ตอนเข้าสู่ระบบ

ระบบต้องเหลือผู้ดูแลระบบอย่างน้อยหนึ่งคนเสมอ เงื่อนไข `NOT_THE_LAST_ADMIN` อยู่ใน `WHERE` ของคำสั่งที่ลดบทบาทและลบบัญชี การตรวจกับการเขียนจึงเป็นคำสั่งเดียวกัน สองคนที่กดลดบทบาทของกันและกันพร้อมกันทำให้ระบบไม่เหลือผู้ดูแลระบบไม่ได้ และลบบัญชีที่ตัวเองกำลังใช้อยู่ก็ไม่ได้

ฐานข้อมูลที่มีอยู่ก่อน ADR นี้ได้บัญชีทุกตัวเป็น `staff` ตามค่าปริยายของคอลัมน์ `ensure_an_admin()` จึงตั้งบัญชีที่เก่าที่สุดเป็นผู้ดูแลระบบตอน `init_db()` ถ้ายังไม่มีผู้ดูแลระบบเลย บัญชีแรกมักเป็นของคนที่ตั้งระบบ คำสั่งนี้รันซ้ำได้และไม่แตะอะไรเมื่อมีผู้ดูแลระบบอยู่แล้ว

## ผลที่ตามมา

โหมดเดสก์ท็อปและไฟล์ `.exe` นับเป็นผู้ดูแลระบบโดยไม่มีบัญชี เพราะคนที่นั่งอยู่หน้าเครื่องเปิดไฟล์ฐานข้อมูลด้วยโปรแกรมอะไรก็ได้อยู่แล้ว ตามเหตุผลเดิมของ [ADR 0001](0001-login-only-for-other-machines.md) แท็บจัดการผู้ใช้งานจึงเปิดได้ในโหมดนั้นด้วย ซึ่งเป็นทางที่ผู้ดูแลสร้างบัญชีแรกจากหน้าเว็บได้โดยไม่ต้องแตะบรรทัดคำสั่ง

`manage_users.py` ยังอยู่และยังใช้ได้ มันเป็นทางเดียวที่เหลือเมื่อไม่มีผู้ดูแลระบบสักคนเข้าระบบได้ เช่น ลืมรหัสผ่านของบัญชีผู้ดูแลระบบคนเดียวที่มี คำสั่งเหล่านั้นสร้างบัญชีเป็นเจ้าหน้าที่ และ `ensure_an_admin()` จะยกบัญชีที่เก่าที่สุดขึ้นมาให้ตอนเปิดแอปครั้งถัดไปถ้ายังไม่มีผู้ดูแลระบบ

ผู้ดูแลระบบที่ลดบทบาทตัวเองลงเป็นเจ้าหน้าที่ทำได้ ถ้ายังมีผู้ดูแลระบบคนอื่นเหลืออยู่ หน้าเว็บอ่านบทบาทใหม่กลับมาทันทีหลังบันทึก แท็บจัดการผู้ใช้งานจึงหายไปจากหน้าจอโดยไม่ต้องโหลดหน้าใหม่

`DELETE /api/positions` ต้องการทั้งสิทธิ์ `delete_all` และที่อยู่ที่เป็นเครื่องแม่ข่าย ข้อจำกัดเรื่องที่อยู่มาจาก ADR 0003 และยังอยู่ตามเดิม ผู้ดูแลระบบที่เปิดจากเครื่องในวงจึงเห็นปุ่ม "ลบทั้งหมด" แต่กดแล้วได้ข้อความปฏิเสธ หน้าเว็บซ่อนปุ่มตามบทบาทอย่างเดียว ไม่ได้ซ่อนตามที่อยู่ของเครื่อง

บทบาทที่สามเพิ่มได้ด้วยการเติมหนึ่งแถวใน `ROLES` และหนึ่งแถวใน `PERMISSIONS` ทั้งการตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ ตัวเลือกบทบาทในหน้าเว็บ และการซ่อนปุ่ม อ่านจากสองตารางนั้น
