# การเข้าสู่ระบบของเครื่องในวง LAN

ในโหมด `run_server.bat` ทุกคนต้องเข้าสู่ระบบก่อนจึงเข้าถึงอะไรได้ รวมถึงคนที่นั่งอยู่หน้าเครื่องแม่ข่ายและเปิดที่ `127.0.0.1` ตาม [ADR 0003](../../../../docs/adr/0003-server-mode-requires-a-login-from-everyone.md) ส่วนโหมดเดสก์ท็อปกับไฟล์ `.exe` ยังยกเว้นให้ loopback ตาม [ADR 0001](../../../../docs/adr/0001-login-only-for-other-machines.md) นโยบายมาจาก host ที่ `serve()` ผูกจริง ไม่ได้มาจากที่อยู่ของผู้เรียกเพียงอย่างเดียว คำขอทุกใบเก็บชื่อผู้บันทึกและผู้แก้ไขล่าสุดไว้เป็นข้อความที่คัดลอกไว้ ไม่ใช่ตัวอ้างอิงไปยังบัญชี ตาม [ADR 0002](../../../../docs/adr/0002-recorder-is-a-copied-name.md) และการลบคำขอทั้งหมดทำได้จากเครื่องแม่ข่ายเท่านั้น

สคิลนี้สวมบทบาทเครื่องในวงด้วยการให้แอป bind `0.0.0.0` แล้วต่อกลับมาที่ IP ของเครื่องตัวเอง `remote_addr` จึงเป็น IP นั้นซึ่งไม่ใช่ loopback แอปเห็นเป็นเครื่องในวงจริงๆ โดยข้อมูลไม่ได้ออกไปนอกเครื่อง

## Sub-features

- `lan-block-api` คำขอ `/api/` จากเครื่องในวงที่ยังไม่เข้าสู่ระบบได้ 401 เป็น JSON ภาษาไทย
- `lan-block-page` หน้าเว็บและไฟล์แนบจากเครื่องในวงที่ยังไม่เข้าสู่ระบบถูกพาไปหน้า `/login`
- `lan-login-ok` เข้าสู่ระบบด้วยบัญชีที่มีอยู่แล้วเข้าถึงได้ และชื่อแสดงผลปรากฏที่หัวหน้าเว็บ
- `lan-login-bad` รหัสผ่านผิดถูกปฏิเสธพร้อมข้อความที่ไม่บอกว่าผิดที่ช่องไหน
- `lan-recorder` คำขอทุกใบที่บันทึกในโหมดนี้เก็บชื่อแสดงผลของคนที่เข้าสู่ระบบเป็นผู้บันทึก รวมถึงใบที่บันทึกจากเครื่องแม่ข่าย ค่า `เครื่องแม่ข่าย` ปรากฏเฉพาะในโหมดเดสก์ท็อป
- `lan-no-delete-all` การลบคำขอทั้งหมดจากเครื่องในวงได้ 403 แม้เข้าสู่ระบบแล้ว
- `lan-logout` ออกจากระบบแล้วกลับไปหน้าเข้าสู่ระบบ และเข้าถึงไม่ได้อีก
- `lan-local-gated` เครื่องแม่ข่ายเองก็ต้องเข้าสู่ระบบในโหมดนี้ และหน้า `/login` ต้องแสดงฟอร์มให้เครื่องแม่ข่าย ไม่ใช่เด้งกลับไป `/` จนวน
- `lan-no-accounts` `serve()` ปฏิเสธที่จะเปิดเซิร์ฟเวอร์เมื่อยังไม่มีบัญชีสักคน
- `lan-desktop-unchanged` โหมดเดสก์ท็อปยังเข้าใช้ได้เลยโดยไม่ต้องเข้าสู่ระบบ

## How to get to it (user POV)

- รัน `run_server.bat` บนเครื่องแม่ข่าย แล้วเครื่องอื่นในวงเปิด `http://<IP เครื่องแม่ข่าย>:5020`
- เครื่องในวงที่ยังไม่เข้าสู่ระบบจะถูกพาไปหน้า `/login` เองทุกครั้งที่เปิดหน้าใด
- เครื่องแม่ข่ายเปิด `http://127.0.0.1:5020` แล้วเจอหน้าเข้าสู่ระบบเหมือนกัน เพราะเซิร์ฟเวอร์แยกไม่ออกว่าคำขอนั้นมาจากคนที่นั่งอยู่หน้าเครื่องจริง
- เมื่อเซสชันหมดอายุระหว่างกรอกแบบ บอ.1 กล่อง `เข้าสู่ระบบอีกครั้ง` ซ้อนทับหน้าเดิม
- กดปุ่ม `ออกจากระบบ` ที่หัวหน้าเว็บ

## Driving it with control_pos.py

Preconditions:

- เปิดอินสแตนซ์ด้วย `$POS app start --lan` ซึ่งรายงาน `lan_url` มาให้
- `$POS doctor` ผ่านทั้ง 8 ข้อ รวมข้อที่ว่าเส้นทางของเครื่องในวงถูกปิดไว้จนกว่าจะเข้าสู่ระบบ
- มีบัญชี `verify` รหัสผ่าน `verify-pass-1` ที่ `app start --lan` สร้างไว้ให้ ตรวจด้วย `$POS users list` ซึ่งคืน `count` เป็น `1` โหมดนี้เปิดไม่ได้เลยถ้าไม่มีบัญชี

- **เครื่องแม่ข่ายเองก็ถูกปฏิเสธ** ยิงจาก `127.0.0.1` โดยไม่มีเซสชัน สั่ง `$POS api GET api/positions --fresh` คำสั่งนี้ **คาดว่าได้ `ok` เป็น `false`** โดย `status` เป็น `401` ข้อนี้คือใจความของ ADR 0003 และเป็นข้อที่แยกโหมดนี้ออกจากโหมดเดสก์ท็อป
- **หน้าเข้าสู่ระบบไม่เด้งเครื่องแม่ข่ายกลับ** สั่ง `$POS browser open` ที่อยู่ที่ได้ลงท้ายด้วย `/login` และ `page.login_form` เป็น `true` ถ้า `/login` ส่งกลับไป `/` เครื่องแม่ข่ายจะวนไม่รู้จบ
- **API ของเครื่องในวงถูกปฏิเสธ** ยิงโดยไม่มีเซสชัน สั่ง `$POS api GET api/positions --from lan --fresh` คำสั่งนี้ **คาดว่าได้ `ok` เป็น `false`** โดย `status` เป็น `401` และ `json.error` เป็น `กรุณาเข้าสู่ระบบ` และ exit code เป็น `1`
- **ยังไม่มีบัญชีก็ยังเข้าไม่ได้** ลองเข้าสู่ระบบด้วยบัญชีที่ไม่มี สั่ง `$POS api GET api/positions --from lan --fresh --login nobody:some-password-1` ผลที่ได้คือ `error` บอกว่าเข้าสู่ระบบไม่สำเร็จ และ `login.json.error` เป็น `ชื่อผู้ใช้งานหรือรหัสผ่านไม่ถูกต้อง`
- **โหมดเดสก์ท็อปยังไม่ถาม** เปิดอินสแตนซ์อีกตัวแบบไม่มี `--lan` สั่ง `$POS app stop` แล้ว `$POS app start` แล้ว `$POS api GET api/positions --fresh` ซึ่งตอบ `200` และ `$POS browser open` ซึ่งได้หน้าแอปโดยไม่ผ่าน `/login` ข้อนี้คือใจความของ ADR 0001 ที่ยังใช้อยู่ จากนั้นกลับไปโหมด LAN ด้วย `$POS app stop` แล้ว `$POS app start --lan`
- **สร้างบัญชีเพิ่ม** สั่ง `$POS users add --username somchai --display "สมชาย ใจดี" --password verify-pass-1` แล้ว `$POS users list` ซึ่งคืน `count` เป็น `2`
- **หน้าเว็บของเครื่องในวงถูกพาไปหน้าเข้าสู่ระบบ** สั่ง `$POS browser open --from lan` ที่อยู่ที่ได้ลงท้ายด้วย `/login` และ `page.login_form` เป็น `true` และชื่อหน้าขึ้นต้นด้วย `เข้าสู่ระบบ`
- **รหัสผ่านผิด** สั่ง `$POS browser fill --select '#username' --value "somchai"` แล้ว `$POS browser fill --select '#password' --value "wrong-password-x"` แล้ว `$POS browser click --text "เข้าสู่ระบบ"` แล้ว `$POS browser read --select '#login-error' --wait-text "ไม่ถูกต้อง"` ข้อความที่ได้คือ `ชื่อผู้ใช้งานหรือรหัสผ่านไม่ถูกต้อง` ซึ่งไม่บอกว่าผิดที่ชื่อผู้ใช้งานหรือที่รหัสผ่าน และที่อยู่ยังเป็น `/login`
- **รหัสผ่านถูก** พิมพ์รหัสผ่านใหม่ **หลังจาก** ข้อความผิดพลาดปรากฏแล้ว สั่ง `$POS browser fill --select '#password' --value "verify-pass-1"` แล้ว `$POS browser click --text "เข้าสู่ระบบ"` แล้ว `$POS browser read --wait-text "เชื่อมต่อแล้ว"` ที่อยู่กลับมาเป็นรากของ `lan_url` และ `page.user` เป็น `สมชาย ใจดี` และ `page.badge` เป็น `เชื่อมต่อแล้ว`
- **บันทึกคำขอในบทบาทเครื่องในวง** กรอกช่องที่จำเป็นแล้วบันทึก สั่ง `$POS browser fill --select '#sec1-container [name="s1_type"]' --value "ทั่วไป"` แล้ว `$POS browser fill --select '#sec1-container [name="s1_level"]' --value "อาวุโส"` แล้ว `$POS browser fill --select '#sec1-container [name="s1_no"]' --value "555"` แล้ว `$POS browser fill --select '#p4_status' --value "อนุมัติ"` แล้ว `$POS browser click --text "บันทึกคำขอ"` ข้อความที่ได้คือ `บันทึกคำขอเรียบร้อยแล้ว`
- **ชื่อผู้บันทึกเป็นชื่อแสดงผล** สั่ง `$POS api GET api/positions` คำขอที่มี `s1_no` เป็น `555` มี `created_by` เป็น `สมชาย ใจดี` ส่วนคำขอตั้งต้นมี `created_by` เป็น `ผู้ตรวจของชุดตรวจ` เพราะ `data seed` เข้าสู่ระบบเป็น `verify` ก่อนเขียน ไม่มีใบไหนเป็น `เครื่องแม่ข่าย` ในโหมดนี้ และเห็นชื่อผู้บันทึกได้ในคอลัมน์ `การบันทึก` ของตาราง ตรวจด้วย `$POS browser click --text "คำขอทั้งหมด"` แล้ว `$POS browser read --table '#tbl' --wait-text "สมชาย ใจดี"`
- **ชื่อผู้บันทึกไม่เปลี่ยนเมื่อลบบัญชี** สั่ง `$POS users remove --username somchai` ซึ่งเป็น dry-run และรายงานบัญชีที่จะลบ แล้ว `$POS users remove --username somchai --apply` แล้ว `$POS api GET api/positions` คำขอใบ `555` ยังมี `created_by` เป็น `สมชาย ใจดี` เหมือนเดิม ข้อนี้คือใจความของ ADR 0002 แล้วสร้างบัญชีกลับด้วย `$POS users add --username somchai --display "สมชาย ใจดี" --password verify-pass-1` ซึ่งต้องเข้าสู่ระบบใหม่
- **ลบทั้งหมดจากเครื่องในวงถูกปฏิเสธ** สั่ง `$POS api DELETE api/positions --from lan --login somchai:verify-pass-1` คำสั่งนี้ **คาดว่าได้ `ok` เป็น `false`** โดย `status` เป็น `403` และ `json.error` เป็น `ลบคำขอทั้งหมดทำได้จากเครื่องแม่ข่ายเท่านั้น` และ `$POS api GET api/positions` ยืนยันว่าคำขอยังอยู่ครบ
- **เครื่องแม่ข่ายลบทั้งหมดได้** สั่ง `$POS api DELETE api/positions --dry-run` เพื่อดูคำขอที่จะส่งก่อน แล้ว `$POS api DELETE api/positions` ซึ่งตอบ `200` และ `$POS api GET api/positions` คืนรายการว่าง
- **ไฟล์แนบก็อยู่ใต้ด่านเดียวกัน** สั่ง `$POS api GET uploads/anything.pdf --from lan --fresh` ซึ่งไม่ได้ไฟล์ แต่ถูกพาไปหน้าเข้าสู่ระบบ สังเกตได้จาก `text` ที่เป็น HTML ของหน้า `/login` ไม่ใช่ JSON
- **ออกจากระบบ** กลับไปที่หน้าของเครื่องในวงแล้วกดออกจากระบบ สั่ง `$POS browser open --from lan` แล้ว `$POS browser click --text "ออกจากระบบ"` แล้ว `$POS browser read --wait-text "เข้าสู่ระบบ"` ที่อยู่ลงท้ายด้วย `/login` และเปิดหน้าหลักซ้ำด้วย `$POS browser open --from lan` ก็ยังถูกพามาหน้านี้อีก
- **หลักฐาน** สั่ง `$POS browser shot --name lan-login-page --with-text` ตอนอยู่หน้าเข้าสู่ระบบ และ `$POS browser shot --name lan-login-error --with-text` ตอนรหัสผ่านผิด และ `$POS browser shot --name lan-logged-in --with-text` ตอนเข้าได้แล้ว ซึ่งต้องเห็นชื่อ `สมชาย ใจดี` ที่หัวหน้าเว็บ และ `$POS browser shot --name lan-recorder --with-text` ตอนตารางแสดงคอลัมน์การบันทึก
- **คืนสภาพ** สั่ง `$POS data seed` แล้ว `$POS app stop`

## Gotchas

- **โหมดนี้ขอรหัสผ่านจาก `127.0.0.1` ด้วย** คำสั่งที่เคยผ่านฉลุยจากเครื่องแม่ข่ายจะได้ 401 ซึ่งถูกต้องแล้ว ใช้ `--login verify:verify-pass-1` เมื่อต้องการผลลัพธ์จริงจากคำสั่ง `api`
- **`serve()` ปฏิเสธที่จะเปิดเมื่อไม่มีบัญชี** ข้อนี้พิสูจน์ด้วย `app start --lan` ไม่ได้ เพราะสคิลสร้างบัญชีให้ก่อนเสมอ เรียก `app.serve(host='0.0.0.0')` ตรงๆ กับฐานข้อมูลเปล่าในโฟลเดอร์ชั่วคราว แล้วดูว่าคืน exit code `1` และพิมพ์คำสั่ง `manage_users.py add` ให้
- **ทางที่ต้องไม่วน** ด่านส่ง `/` ไป `/login` ถ้า `/login` ส่งกลับมาที่ `/` เครื่องแม่ข่ายจะวนไม่รู้จบ เทส `the_login_page_does_not_bounce_this_machine_in_server_mode` กันข้อนี้ไว้ และ `browser open` จับได้เพราะมันรอสัญญาณพร้อมแทนที่จะดูแค่ว่าโหลดเสร็จ
- **คุกกี้ค้างทำให้เส้นทาง 401 หายไป** `$POS api` เก็บคุกกี้เซสชันไว้ใช้ต่อระหว่างคำสั่ง หลังเข้าสู่ระบบสำเร็จหนึ่งครั้ง คำสั่งถัดไปจะได้ 200 ตลอด การพิสูจน์ว่าเครื่องในวงที่ยังไม่เข้าสู่ระบบถูกปฏิเสธ **ต้องใส่ `--fresh`** มิฉะนั้นจะได้ผลที่ดูเหมือนผ่านแต่พิสูจน์อะไรไม่ได้
- **รหัสผ่านผิดใช้เวลาหนึ่งวินาที** `app.py` หน่วงไว้หนึ่งวินาทีเพื่อให้การไล่เดารหัสผ่านไม่คุ้ม แล้วหน้าเว็บล้างช่องรหัสผ่านทิ้งหลังได้คำตอบ การพิมพ์รหัสใหม่ทันทีหลังกดปุ่มจะถูกล้างทับ และคำสั่ง `fill` จะรายงานว่าค่าในช่องไม่ตรงกับที่สั่ง ซึ่งเป็นสัญญาณของ race ไม่ใช่ของแอปพัง ให้รอข้อความผิดพลาดก่อนทุกครั้ง
- แอปไม่ล็อกบัญชีหลังใส่รหัสผิดหลายครั้ง นี่เป็นการตัดสินใจที่ตั้งใจ ไม่ใช่ข้อบกพร่อง ใครก็ได้ในวงจะล็อกเพื่อนร่วมงานออกจากระบบได้ถ้ามีการล็อก
- เบราว์เซอร์แยกคุกกี้ตาม origin หน้าที่เปิดไว้ที่ `127.0.0.1` กับที่เปิดไว้ที่ IP ของเครื่องเป็นสองเซสชันที่ไม่เกี่ยวกัน การเข้าสู่ระบบในฝั่งหนึ่งไม่มีผลกับอีกฝั่ง ซึ่งสะดวกสำหรับการเทียบสองบทบาทในการตรวจรอบเดียว
- เซสชันมีอายุ 12 ชั่วโมงและตรวจที่ฝั่งเซิร์ฟเวอร์ การพิสูจน์กล่อง `เข้าสู่ระบบอีกครั้ง` ต้องให้เซสชันหมดอายุจริง ซึ่งขับไม่ได้ในเวลาที่ยอมรับได้ ให้รายงานว่าข้าม ไม่ใช่รายงานว่าผ่าน
- `users remove` และ `data reset` เป็น dry-run โดยค่าเริ่มต้น ต้องใส่ `--apply` จึงจะทำจริง และคำสั่งหมวด `users` แก้ได้เฉพาะฐานข้อมูลใน `run_dir` บัญชีจริงของหน่วยงานจัดการด้วย `manage_users.py` เท่านั้น
- การลบบัญชีทำให้เซสชันที่เปิดอยู่ในเบราว์เซอร์ใช้ต่อได้จนหมดอายุ เพราะเซสชันไม่ได้ตรวจกลับไปที่ตาราง `users` ทุกคำขอ ให้ตรวจเรื่องชื่อผู้บันทึกจาก API ไม่ใช่จากการคาดว่าหน้าเว็บจะเด้งออก
- โหมด `--lan` bind `0.0.0.0` บนพอร์ตสุ่ม Windows Firewall ปิดขาเข้าไว้โดยค่าเริ่มต้นจึงไม่มีเครื่องอื่นต่อเข้ามาได้ แต่กฎไฟร์วอลล์ที่ `run_server.bat` เพิ่มให้กับพอร์ต 5020 แบบ `remoteip=localsubnet` เป็นของจริงที่สคิลนี้พิสูจน์ไม่ได้
- การเชื่อมต่อในโหมด LAN เป็น `http://` ธรรมดา ไม่ได้เข้ารหัส การเข้าสู่ระบบนี้ออกแบบมากันการเข้าถึงโดยบังเอิญในเครือข่ายสำนักงานที่ควบคุมได้ อย่าสรุปจากการตรวจนี้ว่าระบบทนคนที่ตั้งใจเจาะ
