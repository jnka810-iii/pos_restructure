# บันทึกคำขอ

แท็บกรอกข้อมูลให้ผู้ใช้กรอกแบบ บอ.1 ครบห้าส่วน เพิ่มตำแหน่งได้หลายตำแหน่งต่อคำขอ บันทึกเป็นคำขอใบใหม่หรืออัปเดตใบเดิมที่โหลดมาแก้ ล้างฟอร์มที่กรอกค้างไว้ และเปิดหน้าตัวอย่างสำหรับพิมพ์จากข้อมูลที่อยู่ในฟอร์มตอนนั้น

## Sub-features

- `save-new` บันทึกคำขอใบใหม่จากฟอร์มที่กรอกครบ
- `save-validate` ปฏิเสธการบันทึกและชี้ช่องที่ยังไม่ครบ เมื่อขาดประเภทตำแหน่ง ระดับตำแหน่ง ตำแหน่งเลขที่ หรือสถานะคำขอ
- `save-rows` เพิ่มและลบแถวตำแหน่งในส่วนที่ 1 ถึง 3 และเลขลำดับแถวเรียงใหม่ให้เอง
- `save-update` โหลดคำขอเดิมมาแก้แล้วบันทึกทับใบเดิม ไม่เกิดใบใหม่
- `save-clear` ล้างฟอร์มที่กรอกค้างไว้ โดยถามยืนยันก่อน
- `save-print` เปิดหน้าตัวอย่างแบบ บอ.1 สำหรับพิมพ์หรือบันทึกเป็น PDF

## How to get to it (user POV)

- เปิดแอปแล้วอยู่ที่แท็บ `กรอกข้อมูล` ซึ่งเป็นแท็บเริ่มต้น
- กดแท็บ `กรอกข้อมูล` จากแท็บอื่น
- กดปุ่ม `เพิ่มคำขอ` ในสภาพว่างของแท็บ `คำขอทั้งหมด`
- กดปุ่มรูปดินสอชื่อ `แก้ไขคำขอ` ในแถวของตารางในแท็บ `คำขอทั้งหมด`

## Driving it with control_pos.py

Preconditions:

- `$POS doctor` ผ่านทั้ง 8 ข้อ
- มีคำขอตั้งต้นสองใบ และยังไม่มีคำขอที่ตำแหน่งเลขที่ `777`
- อยู่ที่แท็บ `กรอกข้อมูล` ด้วย `$POS browser open` แล้ว `$POS browser click --text "กรอกข้อมูล"`

- **เปิดฟอร์มเปล่า** ฟอร์มมีแถวตั้งต้นให้แล้วคือส่วนที่ 1 หนึ่งแถว ส่วนที่ 2 หนึ่งแถว ส่วนที่ 3 สามแถว สั่ง `$POS browser read --expr "['sec1','sec2','sec3'].map(s=>document.querySelectorAll('#'+s+'-container .pos-row').length)"` ค่าที่ได้คือ `[1, 1, 3]`
- **บันทึกโดยยังไม่ครบ** กด `บันทึกคำขอ` ทั้งที่ยังไม่ได้กรอกอะไร สั่ง `$POS browser click --text "บันทึกคำขอ"` ผลที่ได้คือ `after.form_errors.shown` เป็น `true` และข้อความมีคำว่า `กรุณาเลือกระดับตำแหน่ง` และ `กรุณาเลือกสถานะคำขอ (ส่วนที่ 4)` และ `after.toast.shown` เป็น `false`
- **กรอกตำแหน่งใหม่** กรอกสามช่องที่จำเป็นของส่วนที่ 1 สั่ง `$POS browser fill --select '#sec1-container [name="s1_type"]' --value "วิชาการ"` แล้ว `$POS browser fill --select '#sec1-container [name="s1_level"]' --value "ชำนาญการพิเศษ"` แล้ว `$POS browser fill --select '#sec1-container [name="s1_no"]' --value "777"` ทุกคำสั่งคืน `ok` เป็น `true` และ `value_now` ตรงกับที่สั่ง
- **เลือกสถานะคำขอ** สั่ง `$POS browser fill --select '#p4_status' --value "อนุมัติ"` ถ้าค่าที่ส่งไม่ใช่ตัวเลือกที่มี คำสั่งจะคืนรายการตัวเลือกที่ถูกต้องมาให้
- **บันทึก** สั่ง `$POS browser click --text "บันทึกคำขอ"` ผลที่ได้คือ `after.toast.shown` เป็น `true` และข้อความคือ `บันทึกคำขอเรียบร้อยแล้ว` และ `after.form_errors.shown` เป็น `false`
- **ยืนยันว่าถูกเก็บจริง** ไปดูที่อีกมุมที่ผู้ใช้เห็นได้ สั่ง `$POS browser click --text "คำขอทั้งหมด"` แล้ว `$POS browser read --table '#tbl' --wait-text "777"` แถวแรกของตารางมี `วิชาการ` `ชำนาญการพิเศษ` `777` และ `counts.total` เพิ่มจาก `2` เป็น `3`
- **ยืนยันผลข้างเคียงฝั่งเซิร์ฟเวอร์** สั่ง `$POS api GET api/positions` คำขอใบบนสุดมี `sec1_rows` ที่มี `s1_no` เป็น `777` และ `created_by` เป็น `เครื่องแม่ข่าย` และ `updated` เป็นค่าว่าง
- **เพิ่มแถวตำแหน่ง** กลับไปแท็บกรอกข้อมูลแล้วกดเพิ่มแถว สั่ง `$POS browser click --text "กรอกข้อมูล"` แล้ว `$POS browser click --text "เพิ่มตำแหน่งใหม่"` แล้ว `$POS browser read --expr "[...document.querySelectorAll('#sec1-container .row-label')].map(e=>e.textContent)"` ค่าที่ได้คือ `["ตำแหน่งใหม่ ที่ 1", "ตำแหน่งใหม่ ที่ 2"]`
- **ลบแถวตำแหน่ง** ลบแถวที่สอง สั่ง `$POS browser click --select '#sec1-container .pos-row:nth-of-type(2) .btn-danger-outline'` แล้วอ่านป้ายแถวซ้ำ เหลือ `["ตำแหน่งใหม่ ที่ 1"]` และเลขลำดับไม่ขาดช่วง
- **แก้คำขอเดิม** โหลดใบที่บันทึกไว้มาแก้ สั่ง `$POS browser click --text "คำขอทั้งหมด"` แล้ว `$POS browser click --text "แก้ไขคำขอ" --nth 0` แล้ว `$POS browser read --wait-text "โหลดคำขอเพื่อแก้ไขแล้ว"` ช่อง `#rec-id` มีค่าเป็น id ของคำขอใบนั้น ตรวจด้วย `$POS browser read --expr "document.getElementById('rec-id').value"`
- **บันทึกทับใบเดิม** เปลี่ยนสถานะแล้วบันทึก สั่ง `$POS browser fill --select '#p4_status' --value "ไม่อนุมัติ"` แล้ว `$POS browser click --text "บันทึกคำขอ"` ข้อความที่ได้คือ `อัปเดตคำขอเรียบร้อยแล้ว` ไม่ใช่ `บันทึกคำขอเรียบร้อยแล้ว` และ `$POS api GET api/positions` ยังมีจำนวนคำขอเท่าเดิม โดยใบนั้นมี `updated` ไม่ว่างแล้ว
- **ล้างฟอร์ม** สั่ง `$POS browser click --text "ล้างฟอร์ม"` กล่องยืนยันชื่อ `ล้างฟอร์ม?` ปรากฏใน `after.open_modal` แล้วกดยืนยันด้วย `$POS browser click --select '#confirmOk'` ช่องในส่วนที่ 4 ว่างทั้งหมด ตรวจด้วย `$POS browser read --expr "document.getElementById('p4_status').value"` ซึ่งเป็นค่าว่าง
- **หน้าตัวอย่างสำหรับพิมพ์** สั่ง `$POS browser click --text "ดูตัวอย่าง / พิมพ์ PDF"` แล้ว `$POS browser read --window latest` หน้าใหม่มีชื่อว่า `บอ.1 – ปรับปรุงตำแหน่ง` และข้อความขึ้นต้นด้วย `บอ.1 – ข้อมูลการปรับปรุงการกำหนดตำแหน่งในสำนักนายกรัฐมนตรี`
- **หลักฐาน** เก็บทั้งตอนบันทึกและผลที่ตามมา สั่ง `$POS browser shot --name save-request-form --with-text` ตอนฟอร์มกรอกครบ และ `$POS browser shot --name save-request-list --with-text` ตอนอยู่ที่แท็บคำขอทั้งหมด และ `$POS browser shot --window latest --name save-request-print` สำหรับหน้าตัวอย่าง ไฟล์ `.json` ต้องมีคำว่า `777` และป้ายสถานะ `เชื่อมต่อแล้ว`
- **คืนสภาพ** สั่ง `$POS browser read --window latest --expr "window.close()"` เพื่อปิดหน้าตัวอย่าง แล้ว `$POS data reset --apply` แล้ว `$POS data seed` ไฟล์หลักฐานไม่ถูกลบ

## Gotchas

- แถวที่ว่างทั้งแถวไม่นับเป็นตำแหน่ง `validateRequest` ข้ามแถวเปล่า การกรอกแค่ช่องเดียวในแถวจะทำให้แถวนั้นกลายเป็นแถวที่ต้องกรอกครบทั้งสามช่องที่จำเป็น
- ช่องในส่วนที่ 1 ถึง 3 ใช้ `name` ซ้ำกันทุกแถว id ถูกสร้างให้ตอน runtime เป็น `s1_type-1` `s1_type-2` ตามลำดับที่สร้าง ซึ่งเปลี่ยนทุกครั้งที่เพิ่มหรือลบแถว **ห้ามอ้างอิง id เหล่านี้** ให้ใช้ `#sec1-container .pos-row:nth-of-type(N) [name="s1_type"]` แทน
- `<select>` และ `<input type="date">` ถูกตั้งค่าแล้วยิง event ให้ ไม่ใช่การกดเลือกจริง เพราะหน้าต่างเลือกเป็น UI ของระบบปฏิบัติการ คำสั่งรายงาน `method` เป็น `set-value+events` ให้รายงานตามนั้น
- `บันทึกคำขอ` เป็นปุ่ม submit ของฟอร์ม การกด Enter ในช่องกรอกจึง submit ฟอร์มด้วย ถ้าตั้งใจทดสอบการกด Enter ต้องรู้ว่ามันคือเส้นทางเดียวกับการกดปุ่ม
- ข้อความแจ้งเตือนหายไปเองหลังเวลาหนึ่ง อ่านผลจาก `after` ของคำสั่ง `click` ซึ่งอ่านทันทีหลังคลิก หรือใช้ `--wait-text` อย่ารอแล้วค่อยอ่าน
- สรุปข้อผิดพลาดและข้อความแจ้งเตือนถูกซ่อนไว้ตอนไม่ใช้ `innerText` ของสิ่งที่ซ่อนอยู่เป็นค่าว่างเสมอ ให้ดู `shown` คู่กับ `text`
- หน้าตัวอย่างสำหรับพิมพ์อ่านจากฟอร์มที่อยู่บนหน้าจอตอนนั้น ไม่ได้อ่านจากคำขอที่บันทึกแล้ว การกดหลังล้างฟอร์มจะได้หน้าว่าง
- ปุ่ม `พิมพ์ / บันทึก PDF` ในหน้าตัวอย่างเรียก `window.print()` ซึ่งเปิดกล่องพิมพ์ของระบบ ขับไม่ได้และห้ามกด
