# แท็บจัดการผู้ใช้งานและบทบาท

ทุกบัญชีมีบทบาทเป็น `admin` หรือ `staff` ผู้ดูแลระบบทำได้ทุกอย่าง เจ้าหน้าที่บันทึกและแก้ไขคำขอได้ แต่ลบคำขอ ลบคำขอทั้งหมด และจัดการบัญชีไม่ได้ ตาม [ADR 0004](../../../../docs/adr/0004-roles-and-user-management-in-the-web.md) สิทธิ์ทั้งหมดอยู่ในตาราง `PERMISSIONS` ตารางเดียวใน `app.py` เซิร์ฟเวอร์บังคับใช้ผ่าน `@requires(<สิทธิ์>)` และหน้าเว็บได้ตารางเดียวกันนั้นไปซ่อนปุ่มที่ติด `data-perm` ไว้ ปุ่มที่บทบาทปัจจุบันกดไม่ได้จึงไม่โผล่เลย ไม่ใช่กดแล้วถูกปฏิเสธ

แท็บ **จัดการผู้ใช้งาน** เปิดได้เฉพาะบทบาทที่มีสิทธิ์ `manage_users` โหมดเดสก์ท็อปนับเป็นผู้ดูแลระบบโดยไม่มีบัญชี แท็บนี้จึงเปิดได้ทั้งในโหมดเดสก์ท็อปและเมื่อผู้ดูแลระบบเข้าสู่ระบบจากเครื่องในวง

## Sub-features

- `users-tab-gated` แท็บจัดการผู้ใช้งานโผล่เฉพาะผู้ดูแลระบบ เจ้าหน้าที่ไม่เห็นแท็บนี้เลย
- `users-list` ตารางบัญชีแสดงลำดับ ชื่อ-นามสกุล ชื่อผู้ใช้ บทบาท วันที่สร้าง และแก้ไขล่าสุด พร้อมตัวแบ่งหน้าที่เลือกจำนวนรายการต่อหน้าได้
- `users-add` เพิ่มบัญชีจากกล่อง `เพิ่มผู้ใช้งาน` โดยกรอกชื่อ-นามสกุล ชื่อผู้ใช้ บทบาท และรหัสผ่าน
- `users-edit` แก้ชื่อ-นามสกุลและบทบาทของบัญชีเดิม ช่องชื่อผู้ใช้ถูกปิดไว้เพราะเปลี่ยนไม่ได้
- `users-password` ตั้งรหัสผ่านใหม่ให้บัญชีอื่นจากปุ่มรูปกุญแจ
- `users-delete` ลบบัญชีจากปุ่มถังขยะ ซึ่งผ่านกล่องยืนยันก่อน
- `users-guards` บัญชีที่กำลังใช้งานอยู่และผู้ดูแลระบบคนสุดท้ายไม่มีปุ่มถังขยะให้กด
- `users-validation` ชื่อผู้ใช้ผิดกติกาและรหัสผ่านสั้นกว่า 8 ตัวขึ้นข้อความไทยในกล่อง และกล่องไม่ปิด
- `users-login-link` บัญชีที่เพิ่งสร้างเข้าสู่ระบบได้ทันที รหัสผ่านที่เพิ่งตั้งใหม่มีผลทันที และบัญชีที่ลบแล้วเข้าไม่ได้อีก
- `role-hides-delete` เจ้าหน้าที่ไม่เห็นปุ่มลบคำขอในตารางและไม่เห็นปุ่ม `ลบทั้งหมด`
- `role-chip` ป้ายบทบาทขึ้นที่หัวหน้าเว็บข้างชื่อผู้ใช้งาน และเปลี่ยนตามบัญชีที่เข้าสู่ระบบ
- `role-live` ผู้ดูแลระบบที่ลดบทบาทตัวเองลงเป็นเจ้าหน้าที่ เห็นแท็บจัดการผู้ใช้งานหายไปทันทีโดยไม่ต้องโหลดหน้าใหม่

## How to get to it (user POV)

- เข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบ แล้วกดแท็บ `จัดการผู้ใช้งาน` บนแถบเมนู
- เปิดด้วย `run.bat` หรือ `run_browser.bat` จากเครื่องแม่ข่าย ซึ่งนับเป็นผู้ดูแลระบบโดยไม่ต้องเข้าสู่ระบบ
- เข้าสู่ระบบด้วยบัญชีเจ้าหน้าที่ แล้วแถบเมนูมีแค่สามแท็บ

## Driving it with control_pos.py

Preconditions:

- เปิดอินสแตนซ์ด้วย `$POS app start --lan` สำหรับเส้นทางที่ต้องมีบทบาทจริง หรือ `$POS app start` สำหรับเส้นทางของโหมดเดสก์ท็อป
- `$POS doctor` ผ่านทั้ง 8 ข้อ
- สร้างบัญชีทั้งสองบทบาทไว้ สั่ง `$POS users add --username somchai --display "สมชาย เจ้าหน้าที่" --password verify-pass-1 --role staff` บัญชี `verify` ที่ `app start --lan` สร้างไว้เป็นผู้ดูแลระบบอยู่แล้ว เพราะ `init_db()` ยกบัญชีที่เก่าที่สุดขึ้นมาเมื่อยังไม่มีผู้ดูแลระบบ ตรวจด้วย `$POS users list` ซึ่งคืน `role` ของทุกบัญชี

- **เข้าสู่ระบบเป็นผู้ดูแลระบบ** สั่ง `$POS browser open --path login --from lan` แล้ว `$POS browser fill --select '#username' --value "verify"` แล้ว `$POS browser fill --select '#password' --value "verify-pass-1"` แล้ว `$POS browser click --select '#login-submit'` จากนั้น `$POS browser read` คืน `page.user` เป็น `ผู้ตรวจของชุดตรวจ` และ `page.controls` มี `จัดการผู้ใช้งาน` อยู่ด้วย
- **เปิดแท็บและอ่านตาราง** สั่ง `$POS browser click --text "จัดการผู้ใช้งาน"` แล้ว `$POS browser read --table '#utbl' --wait-text "somchai"` หัวตารางคือ `ลำดับ ชื่อ-นามสกุล ชื่อผู้ใช้ บทบาท วันที่สร้าง แก้ไขล่าสุด จัดการ` และช่องบทบาทของแต่ละแถวเป็น `ผู้ดูแลระบบ` หรือ `เจ้าหน้าที่` ไม่ใช่ `admin` หรือ `staff`
- **เพิ่มบัญชี** สั่ง `$POS browser click --text "เพิ่มผู้ใช้งาน"` แล้วกรอกสี่ช่องด้วย `$POS browser fill --select '#u_display_name' --value "มาลี ผู้ดูแล"` `--select '#u_username' --value "malee.k"` `--select '#u_role' --value "admin"` `--select '#u_password' --value "malee-pass-1"` แล้ว `$POS browser click --select '#userOk'` ข้อความที่ได้คือ `เพิ่มบัญชีผู้ใช้งานเรียบร้อยแล้ว` และแถวใหม่โผล่ในตาราง
- **บัญชีใหม่เข้าสู่ระบบได้จริง** สั่ง `$POS api GET api/users --from lan --fresh --login malee.k:malee-pass-1` ซึ่งคืน `login.status` เป็น `200` พร้อม `login.json.role` เป็น `admin` และ `status` เป็น `200` ข้อนี้คือสิ่งที่เชื่อมแท็บนี้เข้ากับหน้าเข้าสู่ระบบ อย่าพิสูจน์ด้วยการอ่านตารางอย่างเดียว
- **แก้ชื่อและบทบาท** สั่ง `$POS browser click --text "แก้ไขบัญชี somchai"` แล้ว `$POS browser read --expr "JSON.stringify({u:u_username.disabled, p:uf_password.hidden})"` ซึ่งคืน `true` ทั้งคู่ จากนั้นเปลี่ยนค่าแล้ว `$POS browser click --select '#userOk'` ข้อความที่ได้คือ `บันทึกการแก้ไขบัญชีเรียบร้อยแล้ว` และช่อง `แก้ไขล่าสุด` ของแถวนั้นมีเวลาขึ้นมา
- **ตั้งรหัสผ่านใหม่** สั่ง `$POS browser click --text "ตั้งรหัสผ่านใหม่ของ malee.k"` แล้ว `$POS browser fill --select '#u_password' --value "malee-pass-2"` แล้ว `$POS browser click --select '#userOk'` จากนั้นพิสูจน์ทั้งสองทาง รหัสเดิมด้วย `$POS api GET api/users --from lan --fresh --login malee.k:malee-pass-1` ได้ `login.status` เป็น `401` และรหัสใหม่ได้ `200`
- **ข้อความผิดพลาดอยู่ในกล่อง** ใส่รหัสผ่านสั้นแล้วกดยืนยัน สั่ง `$POS browser read --expr "JSON.stringify({open:!!document.querySelector('.modal.show'), err:document.getElementById('user-error-msg').textContent})"` ซึ่งคืน `open` เป็น `true` และ `err` เป็น `รหัสผ่านต้องยาวอย่างน้อย 8 ตัวอักษร` กล่องต้องไม่ปิด
- **ลบบัญชี** สั่ง `$POS browser click --text "ลบบัญชี malee.k"` แล้ว `$POS browser read` ซึ่งคืน `open_modal` เป็น `['ลบบัญชีผู้ใช้งานนี้?']` แล้ว `$POS browser click --select '#confirmOk'` จากนั้นบัญชีนั้นเข้าสู่ระบบไม่ได้อีก ตรวจด้วย `--login malee.k:malee-pass-2` ซึ่งได้ `401`
- **บัญชีที่ลบไม่ได้ไม่มีปุ่มให้กด** แถวของบัญชีที่กำลังใช้งานอยู่คืนปุ่มแค่สองตัว ส่วนผู้ดูแลระบบคนสุดท้ายพิสูจน์ในโหมดเดสก์ท็อป สั่ง `$POS app start --no-seed` แล้วสร้างผู้ดูแลระบบหนึ่งคนกับเจ้าหน้าที่หนึ่งคน แล้ว `$POS browser open` แล้ว `$POS browser click --text "จัดการผู้ใช้งาน"` แล้ว `$POS browser read --table '#utbl'` แถวของผู้ดูแลระบบคนเดียวนั้นไม่มี `ลบบัญชี` อยู่ในรายการปุ่ม
- **เจ้าหน้าที่ไม่เห็นแท็บและไม่เห็นปุ่มลบ** ออกจากระบบแล้วเข้าใหม่เป็น `somchai` สั่ง `$POS browser read` ซึ่ง `page.controls` ไม่มี `จัดการผู้ใช้งาน` จากนั้น `$POS browser click --text "คำขอทั้งหมด"` แล้ว `$POS browser read --table '#tbl'` ช่องจัดการของทุกแถวมีแค่ `แก้ไขคำขอ` และ `page.controls` ไม่มี `ลบทั้งหมด`
- **นับปุ่มที่มองเห็นจริง** เมื่อต้องการตัวเลขตรงๆ สั่ง `$POS browser read --expr "JSON.stringify({role:me.role, perms:ROLE_PERMS[me.role], visible:[...document.querySelectorAll('[data-perm]')].filter(e=>e.getClientRects().length).length})"` เจ้าหน้าที่คืน `perms` เป็น `[]` และ `visible` เป็น `0`
- **บทบาทเปลี่ยนแล้วหน้าจอตามทันที** เข้าเป็นผู้ดูแลระบบที่มีผู้ดูแลระบบคนอื่นเหลืออยู่ แก้บัญชีของตัวเองเป็นเจ้าหน้าที่ แล้ว `$POS browser read` ซึ่ง `page.controls` ไม่มี `จัดการผู้ใช้งาน` อีก โดยไม่ได้โหลดหน้าใหม่

## Gotchas

- **ตารางเคยรายงานปุ่มที่ซ่อนอยู่ด้วย** `browser read --table` อ่านปุ่มในช่องจัดการจาก `aria-label` เดิมมันไม่กรองด้วยการมองเห็น ปุ่มที่ถูกซ่อนตามบทบาทจึงโผล่ในผลราวกับว่ามีอยู่ ตอนนี้กรองด้วย `vis` แบบเดียวกับ `controls` แล้ว ถ้าผลที่ได้ยังดูขัดกับภาพหน้าจอ ให้ยืนยันด้วย `--expr` ที่นับ `getClientRects().length` ไม่ใช่เชื่อข้อความในตาราง
- **แก้ `templates/index.html` แล้วต้อง `app stop` และ `app start` ใหม่** Flask เก็บเทมเพลตที่แปลงแล้วไว้ในหน่วยความจำเมื่อไม่ได้เปิดโหมด debug การกดโหลดหน้าใหม่จึงยังได้หน้าเดิม อาการคือแก้โค้ดแล้วพฤติกรรมไม่เปลี่ยนเลยทั้งที่ไฟล์เปลี่ยนไปแล้ว ซึ่งอ่านออกยากมากว่าเป็นเพราะอะไร
- **ลำดับการสร้างบัญชีเป็นตัวกำหนดว่าใครเป็นผู้ดูแลระบบ** `init_db()` ยกบัญชีที่เก่าที่สุดขึ้นมาเมื่อยังไม่มีผู้ดูแลระบบเลย บัญชีที่สร้างด้วย `users add` หลังเซิร์ฟเวอร์เปิดแล้วจะไม่ถูกยก ให้ระบุ `--role` ทุกครั้งแทนการเดาจากลำดับ
- **`users add` แก้ได้เฉพาะฐานข้อมูลของการตรวจ** บัญชีจริงของหน่วยงานยังจัดการด้วย `manage_users.py` หรือแท็บจัดการผู้ใช้งานบนแอปจริงเท่านั้น
- **กล่องจัดการบัญชีใช้ id ชุดเดียวกันทั้งสามโหมด** `#u_display_name` `#u_username` `#u_role` `#u_password` และ `#userOk` ไม่เปลี่ยนตามโหมด สิ่งที่เปลี่ยนคือช่องไหนถูกซ่อนและปุ่มยืนยันเขียนว่าอะไร ให้ตรวจโหมดจาก `userTitle.textContent` ไม่ใช่จากชื่อ id
- **ผู้ดูแลระบบจากเครื่องในวงยังเห็นปุ่ม `ลบทั้งหมด`** ปุ่มนั้นถูกซ่อนตามบทบาทเท่านั้น ส่วนข้อจำกัดว่าต้องเป็นเครื่องแม่ข่ายมาจาก ADR 0003 และยังบังคับที่เซิร์ฟเวอร์ กดจากเครื่องในวงแล้วได้ข้อความปฏิเสธ ซึ่งถูกต้องแล้ว ไม่ใช่ข้อผิดพลาดของการซ่อนปุ่ม
- **`--path /` ถูก Git Bash แปลงเป็นเส้นทางของ Windows** ใช้ `$POS browser open` เปล่าๆ เมื่อต้องการหน้าแรก และ `--path login` เมื่อต้องการหน้าเข้าสู่ระบบ
