# แท็บคำขอทั้งหมด

แท็บคำขอทั้งหมดแสดงคำขอทุกใบเป็นตารางเรียงจากใหม่ไปเก่า ให้ค้นหาด้วยข้อความอิสระ กรองตามสถานะคำขอ เปิดคำขอไปแก้ไข ลบทีละใบหรือลบทั้งหมดโดยถามยืนยันก่อน และส่งออกทั้งชุดเป็น CSV หรือ JSON

## Sub-features

- `list-render` แสดงทุกคำขอเป็นแถว พร้อมตัวเลขจำนวนที่แสดงและจำนวนทั้งหมด
- `list-search` ค้นหาด้วยข้อความอิสระ ตรงกับข้อมูลช่องไหนก็ได้ของคำขอ
- `list-filter` กรองตามสถานะคำขอ และใช้ร่วมกับการค้นหาได้
- `list-empty` แยกสภาพ "ยังไม่มีคำขอ" ออกจาก "ไม่พบคำขอที่ตรงกับการค้นหา" และมีปุ่มพาออกจากสภาพนั้น
- `list-delete-one` ลบคำขอทีละใบ โดยกล่องยืนยันบอกว่ากำลังจะลบใบไหน
- `list-delete-all` ลบคำขอทั้งหมด ทำได้จากเครื่องแม่ข่ายเท่านั้น
- `list-export` ส่งออกเป็นไฟล์ CSV และ JSON

## How to get to it (user POV)

- กดแท็บ `คำขอทั้งหมด` ซึ่งมีตัวเลขจำนวนคำขอติดอยู่ที่ชื่อแท็บ
- หลังบันทึกคำขอ แอปยังอยู่ที่แท็บกรอกข้อมูล ผู้ใช้ต้องกดแท็บนี้เองเพื่อมาดูผล

## Driving it with control_pos.py

Preconditions:

- `$POS doctor` ผ่านทั้ง 8 ข้อ
- มีคำขอตั้งต้นสองใบ ใบหนึ่งสถานะ `อนุมัติ` ตำแหน่งเลขที่ `001` กอง `กองการเจ้าหน้าที่` อีกใบสถานะ `อยู่ระหว่างพิจารณา` ตำแหน่งเลขที่ `002` กอง `กองคลัง`
- เปิดแอปด้วย `$POS browser open`

- **เข้าแท็บ** กดแท็บคำขอทั้งหมด สั่ง `$POS browser click --text "คำขอทั้งหมด"` แล้ว `$POS browser read --table '#tbl' --wait-text "001"` ผลที่ได้คือ `active_tab` ขึ้นต้นด้วย `คำขอทั้งหมด` และ `counts` เป็น `{"badge_count": "2", "shown": "2", "total": "2"}` และตารางมีสองแถว
- **หัวตารางและสถานะ** ในผลเดิม `table.headers` มี `ตำแหน่งใหม่ (ส1)` `ระดับ (ส1)` `เลขที่ (ส1)` `สถานะ` และ `จัดการ` และคอลัมน์สถานะของสองแถวคือ `อนุมัติ` กับ `อยู่ระหว่างพิจารณา`
- **ค้นหาที่พบ** ค้นด้วยเลขที่ตำแหน่ง สั่ง `$POS browser fill --select '#search-input' --value "002"` แล้ว `$POS browser read --table '#tbl'` ผลที่ได้คือ `counts.shown` เป็น `1` และ `counts.total` ยังเป็น `2` และตารางเหลือแถวที่มี `002`
- **ค้นหาที่ไม่พบ** ค้นด้วยคำที่ไม่มี สั่ง `$POS browser fill --select '#search-input' --value "ไม่มีคำนี้"` แล้ว `$POS browser read --wait-text "ไม่พบคำขอที่ตรงกับการค้นหา"` ผลที่ได้คือ `counts.shown` เป็น `0` และสภาพว่างมีปุ่ม `ล้างการค้นหา` อยู่ใน `controls`
- **ล้างการค้นหา** กดปุ่มในสภาพว่าง สั่ง `$POS browser click --text "ล้างการค้นหา"` แล้ว `$POS browser read --table '#tbl'` ตารางกลับมาสองแถว และช่องค้นหาว่าง ตรวจด้วย `$POS browser read --expr "document.getElementById('search-input').value"`
- **กรองตามสถานะ** สั่ง `$POS browser fill --select '#filter-status' --value "อนุมัติ"` แล้ว `$POS browser read --table '#tbl'` ผลที่ได้คือ `counts.shown` เป็น `1` และแถวที่เหลือมีสถานะ `อนุมัติ`
- **กรองร่วมกับค้นหา** คงตัวกรองไว้แล้วค้นเลขที่ของอีกใบ สั่ง `$POS browser fill --select '#search-input' --value "002"` แล้วอ่านซ้ำ ผลที่ได้คือ `counts.shown` เป็น `0` เพราะคำขอใบ `002` ไม่ได้อยู่ในสถานะ `อนุมัติ` แล้วคืนสภาพด้วย `$POS browser click --text "ล้างการค้นหา"`
- **ส่งออก CSV** สั่ง `$POS browser click --text "Export CSV"` แล้ว `$POS browser read --wait-text "Export CSV สำเร็จ"` ไฟล์ `pos_<YYYYMMDD>.csv` ปรากฏใน `downloads_dir` ที่ `$POS doctor` รายงานไว้ บรรทัดแรกเป็นหัวคอลัมน์ที่ขึ้นต้นด้วย `created,created_by,file_name` และมีสองบรรทัดข้อมูล
- **ส่งออก JSON** สั่ง `$POS browser click --text "Export JSON"` แล้ว `$POS browser read --wait-text "Export JSON สำเร็จ"` ไฟล์ `pos_<YYYYMMDD>.json` ปรากฏใน `downloads_dir` และเป็นรายการที่มีสองวัตถุ แต่ละวัตถุมี `created_by` เป็น `เครื่องแม่ข่าย`
- **ลบทีละใบ** กดปุ่มรูปถังขยะชื่อ `ลบคำขอ` ของแถวแรก สั่ง `$POS browser click --text "ลบคำขอ" --nth 0` กล่องยืนยันชื่อ `ลบคำขอนี้?` ปรากฏใน `after.open_modal` และตัวกล่องบอกตำแหน่งเลขที่กับสถานะของใบนั้น อ่านด้วย `$POS browser read --select '#confirmBody'`
- **ยกเลิกการลบ** สั่ง `$POS browser click --text "ยกเลิก"` แล้ว `$POS browser read --table '#tbl'` ตารางยังมีสองแถวเท่าเดิม
- **ยืนยันการลบ** สั่ง `$POS browser click --text "ลบคำขอ" --nth 0` แล้ว `$POS browser click --select '#confirmOk'` แล้ว `$POS browser read --wait-text "ลบคำขอเรียบร้อย"` ผลที่ได้คือ `counts.total` เหลือ `1` และ `$POS api GET api/positions` คืนคำขอใบเดียว
- **ลบทั้งหมด** สั่ง `$POS browser click --text "ลบทั้งหมด"` แล้ว `$POS browser click --select '#confirmOk'` แล้ว `$POS browser read --wait-text "ยังไม่มีคำขอ"` ผลที่ได้คือ `counts.total` เป็น `0` สภาพว่างมีปุ่ม `เพิ่มคำขอ` และ `$POS api GET api/positions` คืนรายการว่าง
- **ลบทั้งหมดจากเครื่องในวงต้องถูกปฏิเสธ** เส้นทางนี้พิสูจน์ที่ [`lan-login.md`](./lan-login.md) ไม่ใช่ที่นี่ เพราะต้องเปิดอินสแตนซ์ด้วย `--lan`
- **หลักฐาน** สั่ง `$POS browser shot --name list-filtered --with-text` ตอนกรองอยู่ และ `$POS browser shot --name list-empty --with-text` ตอนสภาพว่าง ไฟล์ `.json` ต้องมี `counts` ที่ตรงกับที่รายงาน
- **คืนสภาพ** สั่ง `$POS data seed` เพื่อใส่คำขอตั้งต้นกลับ

## Gotchas

- การค้นหาเทียบกับ JSON ของทั้งคำขอ ไม่ใช่เฉพาะที่เห็นในตาราง คำที่อยู่ในช่องที่ตารางไม่แสดง เช่น หมายเหตุ ก็ทำให้แถวนั้นตรงด้วย คำขอตั้งต้นทุกใบมี `ชุดตรวจ verify-pos-restructure` อยู่ในหมายเหตุ การค้นคำว่า `ชุดตรวจ` จึงตรงทุกใบ
- ตัวกรองสถานะกับช่องค้นหาทำงานร่วมกันและไม่ถูกล้างเมื่อสลับแท็บ ผลที่ดูเหมือนข้อมูลหาย มักเป็นตัวกรองที่ค้างจากขั้นก่อน ตรวจค่าทั้งสองช่องก่อนสรุป
- `counts.shown` คือจำนวนที่ผ่านตัวกรอง `counts.total` คือจำนวนทั้งหมด การ assert แต่ `total` จะมองไม่เห็นว่าตัวกรองพังหรือไม่
- ตารางวาดใหม่หลัง `loadAll()` เสร็จ และการกดแท็บเป็นคนสั่งโหลด ใช้ `--wait-text` กับค่าที่คาดว่าจะเห็น อย่านอนรอตามเวลา
- ปุ่มแก้ไขและลบในแถวไม่มีข้อความ มีแต่ `aria-label` คือ `แก้ไขคำขอ` และ `ลบคำขอ` ซึ่งซ้ำกันทุกแถว ต้องระบุ `--nth` และ `--nth` นับจากแถวที่มองเห็นในตารางตอนนั้น ซึ่งเปลี่ยนเมื่อมีตัวกรองอยู่
- ข้อความ `ลบคำขอ` เป็นทั้ง `aria-label` ของปุ่มในแถว และข้อความบนปุ่มยืนยันในกล่อง การสั่งหลังกล่องเปิดอยู่จึงอาจไปตรงกับปุ่มในกล่อง ให้กดยืนยันด้วย `--select '#confirmOk'` เสมอ
- `ลบทั้งหมด` ไม่ทำอะไรและขึ้นข้อความ `ยังไม่มีคำขอ` เมื่อไม่มีคำขออยู่แล้ว การเห็นข้อความนี้ไม่ได้แปลว่าลบสำเร็จ
- การส่งออกเป็นการดาวน์โหลดไฟล์ เบราว์เซอร์ headless ปฏิเสธการดาวน์โหลดโดยค่าเริ่มต้น `control_pos.py` เปิดทางให้ลง `downloads_dir` ของอินสแตนซ์แล้ว ถ้าไฟล์ไม่ปรากฏ ให้ดูว่าข้อความ `Export CSV สำเร็จ` ขึ้นหรือไม่ เพื่อแยกว่าพังที่หน้าเว็บหรือพังที่การดาวน์โหลด
- ชื่อไฟล์ที่ส่งออกมีวันที่ของวันนี้ ห้ามเขียนชื่อไฟล์ตายตัวในการ assert ให้จับด้วยแพตเทิร์น `pos_*.csv`
