# ระบบข้อมูลการปรับปรุงการกำหนดตำแหน่งในสำนักนายกรัฐมนตรี

แอปบันทึกข้อมูลแบบ บอ.1 สำหรับคำขอปรับปรุงการกำหนดตำแหน่ง สร้างด้วย Flask กับ SQLite และเปิดเป็นหน้าต่างเดสก์ท็อปผ่าน pywebview ได้ หรือ build เป็นไฟล์ `.exe` ไฟล์เดียวสำหรับ Windows

## ความสามารถ

- กรอกข้อมูลแบบ บอ.1 ครบ 5 ส่วน
  1. คำขอกำหนดตำแหน่ง (ใหม่)
  2. ตำแหน่งที่นำมาปรับปรุงการกำหนดตำแหน่ง
  3. การยุบเลิกตำแหน่งเพื่อควบคุมค่าใช้จ่าย
  4. การพิจารณาของ อกพ. (ครั้งที่ประชุม วันที่ มติ สถานะคำขอ วันที่มีผล หมายเหตุ)
  5. ค่าตอบแทนเฉลี่ยคงเหลือ

  ส่วนที่ 1 ถึง 3 เพิ่มได้หลายตำแหน่งต่อคำขอ
- แนบเอกสารประกอบได้หนึ่งไฟล์ต่อคำขอ รองรับ PDF, Word และ Excel ขนาดไม่เกิน 10 MB
- แท็บคำขอทั้งหมด สำหรับแก้ไขและลบคำขอ
- แท็บสรุปภาพรวม แสดงกราฟด้วย Chart.js
- ส่งออกเป็น CSV, JSON และพิมพ์หรือบันทึกเป็น PDF ทีละคำขอ
- โหมดวง LAN มีการเข้าสู่ระบบรายคน และคำขอทุกใบเก็บชื่อผู้บันทึกกับผู้แก้ไขล่าสุดไว้
- หน้าตาตาม [DESIGN.md](DESIGN.md) และใช้คำตาม [GLOSSARY.md](GLOSSARY.md)

## ความต้องการของระบบ

- Windows 10 หรือ 11
- Python 3.10 ขึ้นไป
- ไม่ต้องต่ออินเทอร์เน็ต ไลบรารีหน้าเว็บและฟอนต์อยู่ใน `static/vendor` ทั้งหมด
- Node.js (ไม่บังคับ) ใช้เฉพาะเทสที่รันฟังก์ชัน JavaScript ของหน้าเว็บ ถ้าไม่มี เทสกลุ่มนั้นจะถูกข้าม

## ติดตั้ง

```bat
cd pos_restructure
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`pyinstaller` ใน `requirements.txt` ใช้เฉพาะตอน build `.exe` ถ้าแค่รันแอปไม่ต้องติดตั้งก็ได้

## วิธีรัน

มีไฟล์ `.bat` ให้ดับเบิลคลิก 3 แบบ ทุกไฟล์ใช้ Python ใน `.venv` ก่อน ถ้าไม่มีจึงใช้ `python` ของเครื่อง

| ไฟล์ | โหมด | เข้าถึงจาก |
| --- | --- | --- |
| `run.bat` | เดสก์ท็อป เปิดหน้าต่าง pywebview | เครื่องนี้เท่านั้น |
| `run_browser.bat` | เปิดในเว็บเบราว์เซอร์ปกติ | `http://127.0.0.1:5020` เครื่องนี้เท่านั้น |
| `run_server.bat` | เซิร์ฟเวอร์ในวง LAN | `http://<IP เครื่องนี้>:5020` ทุกเครื่องในเครือข่าย |

ถ้าไม่ได้ติดตั้ง pywebview คำสั่ง `python app.py` จะรันเป็นเว็บเซิร์ฟเวอร์ที่ `http://127.0.0.1:5020` แทน

`run.bat` และ `run_browser.bat` ปิดแอปตัวเดิมที่ยังค้างอยู่บนพอร์ต 5020 ก่อนเปิดตัวใหม่ (ผ่าน `stop_app.ps1`) เพราะบน Windows แอปหลายตัวเปิดพอร์ตเดียวกันได้ และเบราว์เซอร์จะได้หน้าเก่าจากตัวที่ค้างอยู่ ข้อมูลที่บันทึกแล้วไม่หาย แต่ข้อมูลที่กรอกค้างไว้ในหน้าต่างเดิมและยังไม่ได้บันทึกจะหายไป

`run_server.bat` เปิดพอร์ต 5020 ใน Windows Firewall ให้เองครั้งแรกที่รัน (Windows จะถามสิทธิ์ผู้ดูแลเครื่อง) โดยรับเฉพาะเครื่องที่อยู่ใน subnet เดียวกัน จึงใช้ได้แม้ Windows ตั้งเครือข่ายเป็น Public และแสดง IP ของเครื่องนี้ให้เครื่องอื่นพิมพ์เข้ามา ถ้ากดไม่อนุญาต เครื่องอื่นจะยังเข้าไม่ได้ ให้รันใหม่แล้วกดอนุญาต ลบกฎนี้ได้ด้วย `netsh advfirewall firewall delete rule name=PosRestructure-5020` (ต้องเปิดเป็นผู้ดูแลเครื่อง)

ในโหมด `run_server.bat` ทุกคนต้องเข้าสู่ระบบก่อนถึงจะเข้าถึงอะไรได้ รวมถึงคนที่นั่งอยู่หน้าเครื่องแม่ข่ายและเปิดที่ `http://127.0.0.1:5020` เพราะเมื่อเปิดรับจากภายนอกแล้ว เซิร์ฟเวอร์ไม่มีทางรู้ว่าคำขอที่มาจาก `127.0.0.1` เป็นคนที่นั่งอยู่หน้าเครื่องจริงหรือถูกส่งต่อมาจากที่อื่น ดูเหตุผลที่ [ADR 0003](docs/adr/0003-server-mode-requires-a-login-from-everyone.md)

ส่วน `run.bat`, `run_browser.bat` และไฟล์ `.exe` เสิร์ฟให้ `127.0.0.1` อย่างเดียว จึงยังเปิดใช้ได้เลยโดยไม่ต้องเข้าสู่ระบบ ดูเหตุผลที่ [ADR 0001](docs/adr/0001-login-only-for-other-machines.md)

`run_server.bat` ปฏิเสธที่จะเปิดเซิร์ฟเวอร์เมื่อยังไม่มีบัญชีผู้ใช้งานสักคน เพราะเปิดไปก็ไม่มีใครเข้าได้เลย รวมถึงผู้ดูแลเอง ให้สร้างบัญชีแรกด้วย `manage_users.py add` หรือจากแท็บจัดการผู้ใช้งานใน `run_browser.bat` ก่อนแล้วรันใหม่

> **ข้อควรระวังของโหมด LAN:** การเชื่อมต่อเป็น `http://` ธรรมดา ไม่ได้เข้ารหัส คนที่ดักเครือข่ายในวงได้จะเห็นรหัสผ่านและคุกกี้ การเข้าสู่ระบบนี้ออกแบบมากันการเข้าถึงโดยบังเอิญในเครือข่ายสำนักงานที่ควบคุมได้ ไม่ได้ออกแบบมารับมือคนที่ตั้งใจเจาะ

## บัญชีผู้ใช้งานและบทบาท

ทุกบัญชีมีบทบาทอย่างใดอย่างหนึ่งในสองอย่าง

| บทบาท | บันทึกและแก้ไขคำขอ | ลบคำขอ | ลบคำขอทั้งหมด | จัดการผู้ใช้งาน |
| --- | --- | --- | --- | --- |
| ผู้ดูแลระบบ (`admin`) | ได้ | ได้ | ได้ จากเครื่องแม่ข่ายเท่านั้น | ได้ |
| เจ้าหน้าที่ (`staff`) | ได้ | ไม่ได้ | ไม่ได้ | ไม่ได้ |

เจ้าหน้าที่ไม่เห็นปุ่มที่ทำไม่ได้เลย ไม่ใช่กดแล้วถูกปฏิเสธ เหตุผลของการแบ่งเส้นตรงนี้อยู่ที่ [ADR 0004](docs/adr/0004-roles-and-user-management-in-the-web.md)

### จัดการบัญชีจากหน้าเว็บ

ผู้ดูแลระบบเห็นแท็บ **จัดการผู้ใช้งาน** บนแถบเมนู ใช้เพิ่มบัญชี แก้ชื่อและบทบาท ตั้งรหัสผ่านใหม่ และลบบัญชีได้ครบจากหน้าเว็บ ไม่ต้องแตะบรรทัดคำสั่ง

- ชื่อผู้ใช้ใช้ได้เฉพาะ `a-z 0-9 . _ -` ยาว 3 ถึง 32 ตัว และตั้งแล้วเปลี่ยนไม่ได้ เพราะเป็นสิ่งที่เจ้าของบัญชีพิมพ์ตอนเข้าสู่ระบบ
- ชื่อ-นามสกุลเป็นภาษาไทยได้ และเป็นชื่อที่ไปปรากฏเป็นผู้บันทึกบนคำขอ
- รหัสผ่านยาวอย่างน้อย 8 ตัว เก็บเป็นแฮช ไม่ได้เก็บตัวรหัส
- ระบบต้องเหลือผู้ดูแลระบบอย่างน้อยหนึ่งคน บัญชีที่ลบไม่ได้จะไม่มีปุ่มถังขยะให้กด เช่นเดียวกับบัญชีที่กำลังใช้งานอยู่
- ลบบัญชีแล้วชื่อผู้บันทึกบนคำขอเดิมไม่เปลี่ยน ดู [ADR 0002](docs/adr/0002-recorder-is-a-copied-name.md)

ในโหมด `run.bat`, `run_browser.bat` และไฟล์ `.exe` เครื่องแม่ข่ายนับเป็นผู้ดูแลระบบโดยไม่ต้องเข้าสู่ระบบ แท็บนี้จึงเปิดได้ และเป็นทางที่สร้างบัญชีแรกจากหน้าเว็บได้

### จัดการบัญชีจากบรรทัดคำสั่ง

`manage_users.py` ยังใช้ได้ และเป็นทางเดียวที่เหลือเมื่อไม่มีผู้ดูแลระบบสักคนเข้าระบบได้

```bat
.venv\Scripts\python.exe manage_users.py list
.venv\Scripts\python.exe manage_users.py add somchai "สมชาย ใจดี"
.venv\Scripts\python.exe manage_users.py passwd somchai
.venv\Scripts\python.exe manage_users.py remove somchai
```

คำสั่งเหล่านี้ถามรหัสผ่านทางแป้นพิมพ์สองครั้งโดยไม่แสดงบนหน้าจอ และสร้างบัญชีเป็นเจ้าหน้าที่ ถ้ายังไม่มีผู้ดูแลระบบในระบบเลย บัญชีที่เก่าที่สุดจะถูกตั้งเป็นผู้ดูแลระบบให้ตอนเปิดแอปครั้งถัดไป

เข้าสู่ระบบหนึ่งครั้งใช้ได้ 12 ชั่วโมง ถ้าหมดอายุระหว่างกรอกแบบ บอ.1 หน้าเว็บจะเปิดกล่องเข้าสู่ระบบซ้อนทับให้ แล้วบันทึกต่อให้เอง ข้อมูลที่กรอกค้างไว้ไม่หาย

การลบคำขอทั้งหมดในครั้งเดียวทำได้จากเครื่องแม่ข่ายเท่านั้น เครื่องในวงที่เข้าสู่ระบบแล้วก็ทำไม่ได้ เพราะย้อนกลับไม่ได้และไม่มีเหตุให้ทำจากเครื่องอื่น

## ตั้งให้เครื่องอื่นในวง LAN ใช้งาน

แบ่งเป็นสองฝั่ง เครื่องแม่ข่ายคือเครื่องที่ติดตั้งแอปและเก็บฐานข้อมูล ส่วนเครื่องอื่นในวงใช้แค่เว็บเบราว์เซอร์ ไม่ต้องติดตั้งอะไรเพิ่ม

### ฝั่งเครื่องแม่ข่าย

**1. เปิด Command Prompt ในโฟลเดอร์โปรเจกต์**

เปิดโฟลเดอร์ `pos_restructure` ใน File Explorer พิมพ์ `cmd` ในช่องที่อยู่ด้านบนแล้วกด Enter หรือพิมพ์เอง

```bat
cd /d C:\Users\<ชื่อผู้ใช้ Windows>\Desktop\pos_restructure
```

**2. สร้างบัญชีให้แต่ละคน คนละหนึ่งบัญชี**

```bat
.venv\Scripts\python.exe manage_users.py add somchai "สมชาย ใจดี"
```

โปรแกรมจะถามรหัสผ่านสองครั้ง ตอนพิมพ์จะไม่มีอะไรขึ้นบนหน้าจอ ถือว่าปกติ พิมพ์ให้ครบแล้วกด Enter รหัสผ่านต้องยาวอย่างน้อย 8 ตัว ถ้าสำเร็จจะขึ้นว่า

```
เพิ่มบัญชี somchai (สมชาย ใจดี) แล้ว
```

ทำซ้ำกับทุกคนที่มีสิทธิ์ใช้ แล้วตรวจรายชื่อด้วย

```bat
.venv\Scripts\python.exe manage_users.py list
```

ไม่ควรให้หลายคนใช้บัญชีเดียวกัน เพราะชื่อแสดงผลของบัญชีคือชื่อผู้บันทึกที่ติดไปกับคำขอ

บัญชีที่สร้างด้วยคำสั่งนี้เป็นเจ้าหน้าที่ ซึ่งลบคำขอไม่ได้ บัญชีแรกจะถูกตั้งเป็นผู้ดูแลระบบให้เอง จากนั้นเปลี่ยนบทบาทของคนอื่นได้จากแท็บจัดการผู้ใช้งานบนหน้าเว็บ ดูหัวข้อ [บัญชีผู้ใช้งานและบทบาท](#บัญชีผู้ใช้งานและบทบาท)

**3. เปิดเซิร์ฟเวอร์**

ดับเบิลคลิก `run_server.bat` ครั้งแรกที่รัน Windows จะถามสิทธิ์ผู้ดูแลเครื่องเพื่อเปิดพอร์ต 5020 ให้กด **Yes** จากนั้นหน้าต่างจะแสดงที่อยู่ที่เครื่องอื่นต้องพิมพ์ เช่น

```
[PosRestructure] Other machines on the LAN open:
    http://192.168.208.107:5020   (Ethernet)
```

ต้องเปิดหน้าต่างนี้และเปิดเครื่องไว้ตลอดเวลาที่คนอื่นใช้งาน ปิดหน้าต่างเมื่อไรทุกเครื่องจะใช้งานไม่ได้ทันที ถ้าขึ้นว่า `WARNING: Ethernet (...) is not connected` แปลว่าสาย LAN ไม่ได้เสียบ ให้เสียบสายแล้วรันใหม่

**4. แจ้งผู้ใช้แต่ละคน** เป็นการส่วนตัว ได้แก่ ที่อยู่จากข้อ 3 ชื่อผู้ใช้งาน และรหัสผ่าน

### ฝั่งเครื่องอื่นในวง

1. เปิด Chrome หรือ Edge แล้วพิมพ์ที่อยู่ที่ได้รับ เช่น `http://192.168.208.107:5020`
2. หน้าเข้าสู่ระบบจะขึ้นมา กรอกชื่อผู้ใช้งานและรหัสผ่าน
3. เข้าสู่ระบบหนึ่งครั้งใช้ได้ 12 ชั่วโมง

เครื่องแม่ข่ายเองก็ต้องเข้าสู่ระบบด้วยเมื่อเปิดผ่าน `run_server.bat` ดูหัวข้อ [วิธีรัน](#วิธีรัน)

### งานดูแลบัญชีที่ใช้บ่อย

```bat
rem มีคนลืมรหัสผ่าน ตั้งรหัสใหม่ให้แล้วแจ้งเขา
.venv\Scripts\python.exe manage_users.py passwd somchai

rem มีคนย้ายออก ลบบัญชี ชื่อผู้บันทึกบนคำขอเดิมไม่เปลี่ยน
.venv\Scripts\python.exe manage_users.py remove somchai
```

งานทั้งสองอย่างนี้ทำจากแท็บจัดการผู้ใช้งานบนหน้าเว็บได้เหมือนกัน และไม่ต้องเดินไปที่เครื่องแม่ข่าย

### เครื่องอื่นเข้าไม่ได้

ตรวจตามลำดับนี้ บนเครื่องแม่ข่ายให้รันใน Command Prompt ส่วนคำสั่งที่ขึ้นต้นด้วย `Test-NetConnection` ให้รันใน PowerShell บนเครื่องที่เข้าไม่ได้

| ตรวจอะไร | คำสั่ง | ผลที่ควรได้ |
| --- | --- | --- |
| เซิร์ฟเวอร์เปิดอยู่ไหม (เครื่องแม่ข่าย) | `netstat -ano \| findstr :5020` | มีบรรทัด `0.0.0.0:5020 ... LISTENING` |
| กฎ Firewall มีไหม (เครื่องแม่ข่าย) | `netsh advfirewall firewall show rule name=PosRestructure-5020` | `Enabled: Yes`, `LocalPort: 5020`, `RemoteIP: LocalSubnet` |
| IP ของเครื่องแม่ข่ายตอนนี้ | `ipconfig` | ดูบรรทัด `IPv4 Address` ของการ์ดเครือข่ายที่ใช้จริง |
| เครื่องในวงเห็นพอร์ตไหม (เครื่องที่เข้าไม่ได้) | `Test-NetConnection 192.168.208.107 -Port 5020` | `TcpTestSucceeded : True` |

- ถ้า `TcpTestSucceeded : False` แต่สองข้อแรกผ่าน มักเป็นเพราะสองเครื่องอยู่คนละวงเครือข่าย (กฎ Firewall รับเฉพาะ subnet เดียวกัน) หรือ Wi-Fi สำนักงานเปิดการกันเครื่องลูกข่ายออกจากกัน (client isolation) ต้องให้ฝ่าย IT แก้ที่เครือข่าย
- ถ้าเข้าได้แต่ล็อกอินไม่ผ่าน ให้ตั้งรหัสใหม่ด้วย `passwd` บัญชีไม่ถูกล็อกเมื่อกรอกผิดหลายครั้ง
- ที่อยู่ IP อาจเปลี่ยนเมื่อเครื่องแม่ข่ายรีสตาร์ตหรือต่อเครือข่ายใหม่ ควรให้ฝ่าย IT ตั้ง IP คงที่หรือจอง DHCP ให้เครื่องนี้

## Build เป็น .exe

```bat
.venv\Scripts\pyinstaller.exe --noconfirm --onefile --windowed ^
  --add-data "templates;templates" ^
  --add-data "static;static" ^
  --hidden-import webview ^
  --name "PosRestructure" app.py
```

`--add-data "static;static"` คือไลบรารีหน้าเว็บ ถ้าไม่ใส่บรรทัดนี้ `.exe` จะไม่มี Bootstrap, Chart.js, Font Awesome และฟอนต์ Noto Sans Thai กับ Sarabun ติดไปด้วย และแท็บสรุปภาพรวมจะใช้งานไม่ได้

ไฟล์ที่ได้อยู่ใน `dist\PosRestructure.exe` ตอนรัน แอปจะสร้างฐานข้อมูล ไฟล์ log และโฟลเดอร์ `uploads` ไว้ข้างไฟล์ `.exe`

`.exe` เสิร์ฟที่ `127.0.0.1` อย่างเดียว เปิดให้คนในวง LAN ไม่ได้ จึงไม่ต้องเข้าสู่ระบบและไม่ต้องมี `manage_users.py` ติดไปด้วย

## ข้อมูลและฐานข้อมูล

คำขออยู่ในตาราง `positions` และบัญชีผู้ใช้งานอยู่ในตาราง `users` ทั้งคู่อยู่ใน `pos_restructure.db`

- ส่วนที่ 1 ถึง 3 เก็บเป็น JSON array ในคอลัมน์ `sec1_rows`, `sec2_rows`, `sec3_rows`
- ส่วนที่ 4 และ 5 เก็บแยกคอลัมน์ ขึ้นต้นด้วย `p4_` และ `p5_`
- ไฟล์แนบเก็บชื่อไฟล์ที่ระบบตั้งใหม่ (UUID) ใน `file_name` และชื่อเดิมใน `file_orig_name`
- `created` และ `updated` เก็บเป็น ISO 8601 ค.ศ. หน้าเว็บแปลงเป็นรูปแบบไทยตอนแสดงผล
- `created_by` และ `updated_by` เก็บชื่อแสดงผลของผู้ใช้งานตอนที่บันทึก เป็นข้อความคัดลอกไว้ ไม่ใช่ตัวอ้างอิงไปยังตาราง `users` คำขอที่บันทึกในโหมด `run_server.bat` เก็บชื่อคนที่เข้าสู่ระบบอยู่เสมอ แม้บันทึกจากเครื่องแม่ข่ายเอง ส่วนคำขอที่บันทึกจากโหมดเดสก์ท็อปหรือ `.exe` เก็บคำว่า `เครื่องแม่ข่าย` และคำขอที่บันทึกก่อนมีระบบเข้าสู่ระบบมีค่าว่าง
- หน้าเว็บส่งค่าสี่คอลัมน์นี้มาเองไม่ได้ เซิร์ฟเวอร์เติมให้ทุกครั้ง

ตอนเริ่มแอป `init_db()` สร้างตารางและเพิ่มคอลัมน์ที่ขาดให้อัตโนมัติ และแปลง timestamp รูปแบบเก่า `DD/MM/YYYY HH:MM` เป็น ISO ให้ ไม่ต้องรัน migration เอง

**สำรองข้อมูล:** ปิดแอปก่อน แล้วคัดลอก `pos_restructure.db` กับโฟลเดอร์ `uploads/` ไปเก็บไว้ด้วยกัน ไฟล์ `secret_key` ไม่ต้องสำรอง ถ้าหายไปแอปจะสร้างใหม่ให้ ผลที่เกิดคือทุกคนที่ค้างอยู่ในระบบต้องเข้าสู่ระบบใหม่

## API

ทุก endpoint ตอบเป็น JSON ข้อความ error เป็นภาษาไทยในรูป `{"ok": false, "error": "..."}`

| Method | Path | ใช้ทำอะไร |
| --- | --- | --- |
| GET | `/api/positions` | ดึงรายการทั้งหมด เรียงจากใหม่ไปเก่า |
| POST | `/api/positions` | เพิ่มรายการ |
| PUT | `/api/positions/<id>` | แก้ไขรายการ ตอบ 404 ถ้าไม่มี id นี้ |
| DELETE | `/api/positions/<id>` | ลบรายการพร้อมไฟล์แนบ |
| DELETE | `/api/positions` | ลบทุกรายการพร้อมไฟล์แนบทั้งหมด |
| POST | `/api/upload` | อัปโหลดไฟล์แนบ (multipart field ชื่อ `file`) |
| GET | `/uploads/<ชื่อไฟล์>` | เปิดไฟล์แนบ |
| GET | `/api/ping` | เช็กว่าเซิร์ฟเวอร์ทำงานอยู่ |
| GET | `/login` | หน้าเข้าสู่ระบบ |
| POST | `/login` | เข้าสู่ระบบด้วย `{"username": "...", "password": "..."}` |
| POST | `/logout` | ออกจากระบบ |

คำขอที่เปลี่ยนข้อมูลและส่ง header `Origin` มาจากเว็บไซต์อื่นจะถูกปฏิเสธด้วย 403 เพื่อกัน CSRF

คำขอที่ยังไม่เข้าสู่ระบบจะได้ 401 ถ้าเป็น `/api/` และถูกพาไปหน้า `/login` ถ้าเป็นหน้าเว็บหรือไฟล์แนบ ในโหมด `run_server.bat` ด่านนี้ใช้กับทุกคนรวมถึง `127.0.0.1` ส่วนโหมดเดสก์ท็อปและ `.exe` ยกเว้นให้ `127.0.0.1` ผ่านไปเลย

`DELETE /api/positions` ตอบ 403 เสมอเมื่อเรียกจากเครื่องในวง ข้อนี้ผูกกับที่อยู่ของเครื่อง ไม่ใช่กับบัญชี คนที่นั่งอยู่หน้าเครื่องแม่ข่ายและเข้าสู่ระบบแล้วจึงยังลบทั้งหมดได้

[![tests](https://github.com/jnka810-iii/pos_restructure/actions/workflows/tests.yml/badge.svg)](https://github.com/jnka810-iii/pos_restructure/actions/workflows/tests.yml)

```bat
.venv\Scripts\python.exe test_api.py
```

เทสใช้ฐานข้อมูลและโฟลเดอร์อัปโหลดชั่วคราว ไม่แตะข้อมูลจริง และจบด้วยสรุปจำนวนเทสที่ผ่าน คืนค่า exit code 1 ถ้ามีเทสไม่ผ่าน

เคสที่ต้องใช้ Node เพื่อรัน JavaScript จากหน้าเว็บจะขึ้น SKIP ถ้าเครื่องไม่มี Node สั่ง `--no-skip` เพื่อให้เคสที่ข้ามนับเป็นตก ซึ่งเป็นแบบที่ CI ใช้

```bat
.venv\Scripts\python.exe test_api.py --no-skip
```

GitHub Actions รัน `test_api.py --no-skip` กับ `verify_offline.py` บน `windows-latest` ทุก pull request ตั้งค่าอยู่ใน `.github/workflows/tests.yml`

### ตรวจว่าใช้งานออฟไลน์ได้

```bat
.venv\Scripts\python.exe verify_offline.py
```

สคริปต์เปิดแอปบนพอร์ตว่าง แล้วสั่ง Edge หรือ Chrome แบบ headless ให้เปิดหน้านั้นโดยทุกโฮสต์นอกจาก 127.0.0.1 หาที่อยู่ไม่เจอ ซึ่งเป็นสภาพเดียวกับเครื่องที่ไม่มีเน็ต แล้ววัดจากในเบราว์เซอร์ว่า Chart.js, Bootstrap, ไอคอน และฟอนต์ไทยมาครบ ภาพหน้าจอที่ได้อยู่ในโฟลเดอร์ temp สั่งที่อื่นได้ด้วย `--shot`

## สคริปต์ดูแลระบบ

ทั้งสองสคริปต์เป็น dry-run โดยค่าเริ่มต้น แสดงแค่สิ่งที่จะทำ ต้องใส่ `--apply` จึงจะทำจริง

```bat
REM ลบไฟล์แนบที่ไม่มีรายการไหนอ้างถึง
.venv\Scripts\python.exe cleanup_orphans.py
.venv\Scripts\python.exe cleanup_orphans.py --apply

REM ลบคอลัมน์ที่โค้ดไม่ใช้แล้ว (สำรองฐานข้อมูลเป็น .bak ให้ก่อนเสมอ)
.venv\Scripts\python.exe migrate_schema.py
.venv\Scripts\python.exe migrate_schema.py --apply
```

ส่วน `vendor_assets.py` ดาวน์โหลดไลบรารีหน้าเว็บลง `static/vendor` ใหม่ทั้งโฟลเดอร์ ต้องต่อเน็ตตอนรัน ใช้เมื่อขึ้นเวอร์ชัน Bootstrap, Chart.js, Font Awesome หรือฟอนต์ Noto Sans Thai และ Sarabun โดยแก้ตาราง `ASSETS` ในสคริปต์ก่อน แล้วรัน `verify_offline.py` ซ้ำ

```bat
.venv\Scripts\python.exe vendor_assets.py
```
